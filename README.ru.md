### Скрытые каналы DNS — с измерениями.

**SIREN читает DNS-трафик, извлекает поведенческие признаки и оценивает каждый
блок (клиент, домен, временное окно) восемью объяснимыми детекторами — а затем
доказывает, насколько хорошо это работает.**

## Зачем нужен SIREN

DNS — единственный протокол, который почти любая сеть выпускает наружу. Именно
поэтому через него и выносят данные. Большинство публичных «детекторов DNS
exfiltration» — это одна проверка энтропии в Python-скрипте: без тестов, без
эталонной разметки, без понимания, работает ли это вообще.

SIREN устроен наоборот:

- **Объяснимость по построению.** Каждое срабатывание показывает признаки,
  измеренное значение и порог, который был превышен.
- **Согласованность, а не догадки.** Один сильный признак не даёт высокого
  вердикта: веса подобраны так, чтобы вердикт требовал нескольких независимых
  сигналов.
- **Измерения, а не обещания.** Детерминированный генератор создаёт размеченный
  трафик, а `siren eval` считает precision, recall, F1 и FPR по порогам. Любое
  число в этом README воспроизводится двумя командами.
- **Без нативных зависимостей.** Парсер PCAP и DNS написан на чистом Rust — без
  libpcap, без Npcap, без root. Одинаково работает на Linux, Windows и macOS.

> SIREN — инструмент обнаружения и анализа. Он не стоит в разрыве и не блокирует
> трафик.

## Установка

### Требования

- Rust **1.75+** (рекомендуется `rustup`)
- Без libpcap, без Npcap, без root

### Linux / macOS

```bash
git clone https://github.com/raxwqx/SIREN.git
cd SIREN
cargo build --release
./target/release/siren --help
```

Установка в систему:

```bash
sudo install -m 0755 target/release/siren /usr/local/bin/siren
```

### Windows (PowerShell)

```powershell
git clone https://github.com/raxwqx/SIREN.git
cd SIREN
cargo build --release
.\target\release\siren.exe --help
```

Добавить в `PATH` текущей сессии:

```powershell
$env:Path += ";$PWD\target\release"
siren --version
```

> Windows Terminal (или любой терминал с поддержкой VT) покажет цветной вывод.
> При перенаправлении stdout SIREN автоматически переходит на простой текст.

## Быстрый старт

```bash
# 1. разобрать захват
siren analyze capture.pcap

# 2. изменить окно
siren analyze capture.pcap --window 300

# 3. показать доказательства по каждому Finding
siren analyze capture.pcap --window 300 --explain

# 4. машиночитаемый вывод
siren analyze capture.pcap --format json  > findings.json
siren analyze capture.pcap --format sarif > siren.sarif

# 5. уронить CI-задачу при серьёзном срабатывании
siren analyze capture.pcap --fail-on high

# 6. воспроизвести оценку из этого README
siren gen --out data/eval.jsonl --seed 42
siren eval data/eval.jsonl --window 300
```

## Как это работает

```text
   PCAP / PCAPNG*            JSONL-логи
        │                       │
        └───────────┬───────────┘
                    ▼
            ┌───────────────┐
            │  DNS-парсер   │  Ethernet · VLAN · IPv4 · IPv6 · UDP/53
            └───────┬───────┘
                    ▼
            ┌───────────────┐
            │  группировка  │  (клиент, домен, окно)
            └───────┬───────┘
                    ▼
            ┌───────────────┐
            │   признаки    │  энтропия · длина метки · qps · NXDOMAIN
            └───────┬───────┘  доля TXT · кодировка · CV интервалов · fanout
                    ▼
            ┌───────────────┐
            │  8 детекторов │  каждый даёт 0..1 + доказательство
            └───────┬───────┘
                    ▼
            ┌───────────────┐
            │   скоринг     │  risk = 100 × Σ(вес × скор)
            └───────┬───────┘
                    ▼
        таблица  ·  JSON  ·  SARIF
```

\* PCAPNG распознаётся и сопровождается подсказкой о конвертации
(`editcap -F pcap`). Нативная поддержка — в плане.

### Сигналы обнаружения

| Сигнал | Вес | Когда срабатывает | MITRE ATT&CK |
|---|---:|---|---|
| `entropy` | 0.20 | средняя энтропия метки **> 4.3 бит/символ** | T1001 |
| `label-length` | 0.16 | любая метка **> 20 символов** | T1071.004 |
| `query-rate` | 0.18 | **> 0.3 запроса/с** к одному домену | T1048 |
| `nxdomain` | 0.11 | **> 25%** ответов — NXDOMAIN | T1568.002 |
| `qtype` | 0.09 | **> 30%** запросов — TXT | T1071.004 |
| `encoding` | 0.15 | **> 20%** меток похожи на hex/base32/base64 | T1001 |
| `beaconing` | 0.07 | **CV интервалов < 0.35** при ≥ 6 запросах | T1071.004 |
| `fanout` | 0.04 | **≥ 20** различных меток под одним доменом | T1568.002 |

`risk = 100 × Σ(вес × скор_сигнала)` — один сигнал по дизайну не может дать
высокий вердикт. Таблицу можно напечатать из бинарника: `siren signals`.

## Оценка качества

SIREN поставляется с детерминированным генератором трафика: обычный сёрфинг,
CDN-«сложные негативы» (длинные hex-метки), высокочастотная телеметрия,
кодированные туннели (hex, base32, base64), туннели с NXDOMAIN и намеренно
медленные туннели.

```bash
siren gen --out data/eval.jsonl --seed 42
siren eval data/eval.jsonl --window 60 --json
siren eval data/eval.jsonl --window 300 --json
```

Датасет: **17 719 событий**, **96 доменов**, seed `42`, порог выбирается по
лучшему F1.

| Окно | Блоки | Положительные | Precision | Recall | F1 | FPR |
|---|---:|---:|---:|---:|---:|---:|
| 60 с | 1 717 | 157 | **1.000** | 0.790 | 0.883 | 0.000 |
| 300 с | 657 | 98 | **0.989** | **0.929** | **0.958** | 0.002 |

**Читайте честно:** на 60 с детектор точный, но слеп к медленным туннелям —
два запроса в минуту не дают достаточных доказательств внутри минутного блока.
Расширьте окно — recall растёт, но появляется задержка обнаружения и один
ложноположительный результат. Ради этого компромисса окно и сделано
параметром.

Воспроизведите сами: генератор seeded, числа стабильны.

### Производительность

| Нагрузка | События | Время | Скорость |
|---|---:|---:|---:|
| JSONL, release | 17 719 | 61 мс | ~290 тыс. событий/с |
| JSONL, 5× датасет | 88 595 | 296 мс | ~299 тыс. событий/с |

Одно ядро, без SIMD, без unsafe.

## Справочник CLI

```text
siren analyze <ВХОД> [ОПЦИИ]
siren gen     --out <ПУТЬ> [--seed N]
siren eval    <ВХОД> [ОПЦИИ]
siren signals
```

### `siren analyze`

| Опция | По умолчанию | Описание |
|---|---|---|
| `--window <СЕК>` | `60` | Размер блока |
| `--min-queries <N>` | `3` | Игнорировать блоки с меньшим числом запросов |
| `--min-risk <0-100>` | `12` | Минимальный риск для вывода |
| `--format <table\|json\|sarif>` | `table` | Формат вывода |
| `--allowlist <ФАЙЛ>` | — | По одному домену на строку |
| `--explain` | выкл | Печатать доказательства |
| `--fail-on <low\|medium\|high\|critical>` | выкл | Выход с кодом `2` |
| `--no-banner` | выкл | Без баннера |

### `siren eval`

| Опция | По умолчанию | Описание |
|---|---|---|
| `--window <СЕК>` | `60` | Размер блока |
| `--min-queries <N>` | `3` | Игнорировать редкие блоки |
| `--json` | выкл | Машиночитаемый отчёт |

## Форматы ввода

### PCAP

Классические файлы libpcap (`0xa1b2c3d4`, микро- или наносекунды).
Поддерживаемые типы: Ethernet (с 802.1Q/QinQ), raw IP, Linux SLL/SLL2.
В v0.1 — только 53/UDP.

### JSONL

Один JSON-объект на строку:

```json
{"ts":1700000000.0,"client":"10.0.0.5","qname":"a.example.com","qtype":1,"rcode":0,"size":55}
{"ts":1700000001.2,"client":"10.0.0.5","qname":"k3j4h5g6.tunnel.net","qtype":16,"rcode":3,"size":90}
```

Добавьте `"label": 0|1`, чтобы запустить `siren eval` на своей разметке.

## Проектные решения

1. **Windows — первого класса.** Чистый Rust не требует Npcap и прав
   администратора. Один бинарник на Windows, Linux и macOS.
2. **Объяснимость вместо чёрного ящика.** Никакого ML в горячем пути. Любой скор
   пересчитывается вручную по напечатанным признакам.
3. **Согласованность.** Страница с ресурсами с CDN на hex-метках выглядит
   подозрительно для наивной проверки энтропии. SIREN требует совпадения
   частоты, типов и тайминга.
4. **Воспроизводимость.** Seeded-генератор, пороги-константы, тест на сумму
   весов = 1.0.
5. **Скучно там, где нужно.** Без unsafe, без глобального состояния, без
   скрытого I/O.

## FAQ

**Это IDS?**
Нет. Офлайн-анализатор и движок обнаружения. Читает трафик, но не стоит в
разрыве и не блокирует.

**Нужен root или Npcap?**
Нет. Укажите файл. Живому захвату (в плане) понадобятся права на захват.

**Ловит ли DNS over HTTPS?**
Пока нет. DoH — задача v0.2.

**Почему Rust, а не Python?**
Один статический бинарник, без интерпретатора и зависимостей на Windows,
сотни тысяч событий в секунду.

**Можно свои метки?**
Да: `"label": 0|1` в JSONL и `siren eval`.

**Оценка настоящая?**
Синтетическая, но размеченная и детерминированная. Она измеряет внутреннюю
согласованность детектора, а не реальную распространённость. Следующий шаг —
ваши собственные размеченные захваты; команда `eval` именно для этого.
